## 1. 技术栈定稿

| 层次 | 技术选型 | 说明 |
|---|---|---|
| 数据库 | MySQL 8.x（utf8mb4），13 张表 | 外键、唯一索引、CHECK 约束在 DDL 中落地 |
| 后端 | Java 25（Temurin）+ Spring Boot 3.x + MyBatis-Plus | Spring Security 仅用 BCrypt；JWT（jjwt）做登录态 |
| 定时任务 | Spring @Scheduled（每日 02:00） | 过期扫描与临期标记 |
| 前端 | Vue 3 + Vite + Element Plus + axios + Pinia | 单页应用，按角色分 4 端页面 |
| 构建工具 | Maven（后端）、npm（前端）、Git（版本管理） | 仓库根目录为当前工程 |

## 3. 各步骤详情

### 第 0 步：环境与工程骨架

**做什么**：

1. 安装/确认 MySQL 8，创建数据库 `vaccine_db`（utf8mb4）；
2. 创建 Spring Boot 3.x 后端工程（backend/，JDK 25 + Maven），引入依赖：spring-boot-starter-web、mybatis-plus、mysql-connector-j、spring-security-crypto（仅 BCrypt）、jjwt、lombok、validation；
3. 创建 Vue 3 前端工程（frontend/，Vite + Element Plus + axios + Pinia）；
4. 编写 application.yml：数据源、服务端口、JWT 密钥与过期时间、预警常量（near-expiry-days=30、low-stock-threshold=10、cancel-deadline-hours=24）。

**产出物**：可启动的后端工程、可启动的前端工程、空数据库 vaccine_db、application.yml。

**怎么验收**：

- [ ] 后端启动无报错，`GET /api/ping` 返回 200；
- [ ] 启动日志无数据源连接异常（后端成功连上 vaccine_db）；
- [ ] 前端 `npm run dev` 启动，浏览器打开首页正常显示；
- [ ] application.yml 中 4 项常量配置齐全且与需求文档 5.4 一致。

### 第 1 步：数据库建表脚本（13 张表）

**做什么**：

1. 编写 `sql/01_schema.sql`：13 张表 DDL，落地需求文档 4.1 的约束：
   - 外键：batch 复合外键 (vaccine_id, manufacturer_id) → vaccine_manufacturer；vaccine_stock 复合外键 (vaccine_id, manufacturer_id) → vaccine_manufacturer，以及 supply_id、batch_id 等全部外键；
   - 唯一约束：user.username / user.id_card、manufacturer.license_no / manufacturer.username、nurse.employee_no、institution_admin.username、super_admin.username、vaccine_manufacturer 联合主键、batch 的 (manufacturer_id, batch_no) 唯一、appointment 唯一索引 (user_id, shift_id)；
   - CHECK 约束：quantity ≥ 0、locked_quantity ≥ 0、max_appointments > 0、doses_required ≥ 1、received_quantity ≤ quantity（如 MySQL 版本支持，否则由应用层兜底）；
2. 编写 `sql/02_data.sql` 演示数据：1 个超级管理员、2 家生产商（含登录账号）、2 家机构及机构管理员、每机构 2 名护士、若干疫苗（覆盖多剂次与多厂商共享疫苗）、批次、班次、测试居民用户；
3. 在空库上执行两脚本，确认可重复执行（脚本幂等）。

**产出物**：sql/01_schema.sql、sql/02_data.sql。

**怎么验收**：

- [ ] 空库上按 01→02 顺序执行无报错；重复执行同一脚本不报错；
- [ ] `SHOW TABLES` 共 13 张表，名称与需求文档 4.1 一致；
- [ ] 反例测试（以下 SQL 均应被数据库拒绝）：
  - 插入 (vaccine_id, manufacturer_id) 不存在于 vaccine_manufacturer 的 batch 记录；
  - 插入同一 (user_id, shift_id) 的两条 appointment 记录；
  - 插入 quantity 为负数的 vaccine_stock 记录；
- [ ] 演示数据中：某疫苗在 vaccine_manufacturer 中有 2 条生产商记录（多厂商生效）。

### 第 2 步：账号与登录模块

**做什么**：

1. 建立 4 类账号的实体/Mapper（user、institution_admin、manufacturer、super_admin）；
2. BCrypt 工具类与注册接口（密码入库前加密）；
3. 登录接口：按角色查表 → BCrypt 校验 → 签发 JWT（携带角色与主体 ID）；
4. JWT 拦截器 + 角色权限注解：居民/机构管理员/生产商/超级管理员四类接口按角色隔离；
5. 超级管理员功能：注册机构（事务内同时创建 institution + institution_admin）、注册生产商（manufacturer 含登录账号）。

**产出物**：登录/注册接口、JWT 鉴权链路、超管注册接口。

**怎么验收**：

- [ ] 4 类账号分别登录成功，返回 token 中角色字段正确；
- [ ] 错误密码返回 401；不存在用户返回 401（不泄露账号是否存在）；
- [ ] 无 token 访问任意业务接口返回 401；
- [ ] 居民 token 调用机构管理接口返回 403；机构管理员 token 操作他机构数据返回 403；
- [ ] 数据库中 password 字段为 BCrypt 密文（以 `$2a$` 开头），无明文；
- [ ] 注册机构后 institution 与 institution_admin 两条记录同时生成且关联正确。

### 第 3 步：基础数据管理模块

**做什么**：

1. 生产商端：疫苗维护（创建/修改疫苗时可勾选本厂关联，写入 vaccine_manufacturer）；批次生产记录维护（batch：批次号、生产日期、有效期、生产数量）；
2. 机构管理员端：护士维护；班次维护（创建班次时 institution_id 由系统取护士所属机构自动写入；排班页展示本机构各疫苗库存、临期/低库存预警信息）；
3. 超级管理员端：机构/生产商/疫苗的兜底增改查。

**产出物**：疫苗/批次/护士/班次 CRUD 接口，排班页库存预警数据接口。

**怎么验收**：

- [ ] 创建疫苗时可选多个生产商，vaccine_manufacturer 落库正确；
- [ ] 创建班次后 shift.institution_id 与所选护士的机构一致（无法出现跨机构班次）；
- [ ] 排班页数据接口返回该机构疫苗库存 + 临期/低库存预警标志；
- [ ] 生产商仅能维护本厂疫苗关联，跨厂操作被拒绝；
- [ ] 各角色对基础数据的操作范围符合 N-06 权限隔离。

### 第 4 步：供货与入库模块

**做什么**：

1. 生产商端：创建供货记录 supply（选择本厂批次、目标机构、配送数量、配送日期）；
2. 机构管理员端：查询本机构待入库供货记录，确认入库（支持分批）：事务内新增/累加 vaccine_stock（institution_id、vaccine_id、manufacturer_id、batch_no、production_date、expiry_date 从 batch 与 supply 带入，supply_id、batch_id 落库），received_quantity 累加；received_quantity 达到 quantity 时 supply 状态置"已入库"；
3. 入库校验：单次入库量 ≤ 剩余供货量（quantity − received_quantity）。

**产出物**：供货记录接口、分批入库接口。

**怎么验收**：

- [ ] 供货记录创建后，目标机构可见该待入库记录；
- [ ] 确认入库后 vaccine_stock 新增记录，数量、批次号、生产商、有效期与 batch 表一致；
- [ ] 超额入库（超出剩余供货量）被拒绝并提示；
- [ ] 分 2 次入库后 received_quantity 累加正确，满额后 supply 状态自动置"已入库"，不可再入库；
- [ ] 追溯查询：由一条 vaccine_stock 记录能查到 supply（供货日期、数量）与 batch（生产商、生产日期）。

### 第 5 步：用户端查询与预约模块（核心）

**做什么**：

1. 用户端查询接口：疫苗列表、机构查询（无正常批次库存的机构+疫苗组合隐藏）、机构某疫苗批次余量、班次列表（名额 > 0）；
2. 预约接口（事务 + `SELECT ... FOR UPDATE` 行锁），按 5.3 顺序执行：
   - FEFO 选批次（status=1 且 quantity>0，expiry_date 最早）并锁行；
   - 校验班次名额（status=1 且 current_count < max_appointments）并锁行；
   - 剂次校验、重复预约校验、时段冲突校验；
   - 库存 quantity−1 / locked+1；班次 current_count+1；插入 appointment（dose_number、stock_id、appointment_date = shift_date）；
3. 取消预约接口：status=1 且当前时间 ≤ 班次开始前 24 小时才可取消；释放库存与名额，写 cancel_reason；
4. 我的预约接口：列表含状态与取消原因。

**产出物**：预约提交/取消/查询接口，FEFO 服务，并发控制逻辑。

**怎么验收**：

- [ ] FEFO：构造 3 个有效期不同的正常批次，预约后锁定的批次是有效期最早的一个（核对 appointment.stock_id）；
- [ ] 并发不超卖：某批次 quantity=1 时并发 10 个预约请求，仅 1 个成功，其余失败且库存不为负（JMeter 或脚本模拟）；
- [ ] 班次满员（current_count = max_appointments）后预约被拒绝；
- [ ] 剂次：无第 1 剂"已完成"记录时预约第 2 剂被拒；第 1 剂完成后可约第 2 剂；第 3 剂超出 doses_required 被拒；
- [ ] 重复预约：同一用户预约同一班次两次，第二次被拒（应用层 + 唯一索引双保险）；
- [ ] 时段冲突：同一用户同一时段预约另一班次被拒；
- [ ] 取消：取消后 quantity、current_count 恢复；班次开始前 24 小时内取消被拒；
- [ ] 无库存隐藏：库存为 0 的机构+疫苗组合不出现在用户查询结果中。

### 第 6 步：接种完成与接种记录模块

**做什么**：

1. 机构管理员端：本机构待接种预约列表；"确认接种"接口（事务）：校验 status=1 → locked_quantity−1 → vaccination_time=当前时间 → status=2；
2. 用户端：接种记录接口（已完成预约 + 关联查询疫苗名、批次号、机构、护士姓名、接种时间、剂次）。

**产出物**：确认接种接口、接种记录查询接口。

**怎么验收**：

- [ ] 确认接种后 locked_quantity 减 1，quantity 不变；
- [ ] vaccination_time 已写入，status 变为 2；
- [ ] 同一预约重复"确认接种"被拒绝（幂等）；
- [ ] 已完成的预约不可取消、不可再次确认；
- [ ] 用户接种记录页展示：疫苗名称、批次编号、接种护士（来自班次护士）、接种时间、第几剂，全部正确。

### 第 7 步：库存预警与定时任务模块

**做什么**：

1. Spring @Scheduled（cron 每日 02:00）扫描任务，事务内处理：
   - 临期：status=1 且 expiry_date − today ≤ 30 → status=2；
   - 过期：expiry_date < today 且 status ∈ {1,2} → status=3；若 locked_quantity>0：释放锁定（回加 quantity）、关联待接种预约自动取消（cancel_reason="疫苗批次过期"）、班次名额释放；
2. 机构端预警接口：临期列表（标黄）、过期列表（红色封锁）、低库存列表（合计 ≤ 10）；
3. 销毁接口：status=3 批次销毁，校验 locked_quantity=0，否则先取消关联预约；quantity 置 0、status=4。

**产出物**：定时扫描任务、预警查询接口、销毁接口。

**怎么验收**：

- [ ] 构造"距过期 10 天"与"已过期"的批次，手动触发任务后状态分别变为 2、3；
- [ ] 过期批次存在待接种预约时，任务执行后：预约 status=3 且 cancel_reason="疫苗批次过期"；locked_quantity 归零并回加 quantity；班次 current_count 相应减少；
- [ ] 管理端预警接口正确返回临期/过期/低库存三类列表；
- [ ] 存在锁定预约的过期批次销毁被拒；取消预约后可销毁；销毁后记录仍在库中（status=4 可查）；
- [ ] 用户端"我的预约"能看到因批次过期被取消的预约及原因。
