## 1. 引言

### 1.1 编写目的

本文档依据《选题.md》将选题说明转化为正式的需求规格说明，作为后续数据库设计、编码实现、测试验收的依据。第 7 章为决策记录：标注【代决】的条目由文档按真实业务场景代为决策，项目负责人如有异议可直接修改。

### 1.2 系统定位

疫苗管理系统是面向"疫苗从生产到接种全链路管理"的数据库应用系统，以 **"用户选疫苗 → 选机构 → 选护士班次 → 预约接种"** 为核心流程，将**生产商供货 → 机构入库 → 用户预约 → 护士接种**四个环节串联，实现每支疫苗来源可查、去向可追。

### 1.3 术语定义

| 术语 | 说明 |
|---|---|
| FEFO | First Expiry First Out，近效期优先出库策略，预约时自动选择有效期最早的批次 |
| 班次 | 某机构某护士在特定日期、时段（如 08:00–12:00）的排班，是用户预约选择的直接对象 |
| 批次 | 生产商某次生产的一批疫苗，具有唯一批次号，是库存管理与追溯的基本单位 |
| 供货记录 | 生产商向机构配送疫苗的记录（supply 表），机构凭此入库，支持分批入库确认 |
| 剂次 | 疫苗需接种的第几针（dose_number），如 2 剂次疫苗分为第 1 剂、第 2 剂 |
| 库存锁定 | 用户预约时将 1 支库存从"可用量"转入"已锁定量"，接种确认后才真正扣减，防止超卖 |
| 取消原因 | 预约被取消的缘由（用户取消/班次停诊/疫苗批次过期），写入 cancel_reason 字段 |
| 临期预警 | 距有效期 ≤ 30 天的批次自动标记预警（status = 2），仍可正常出库 |
| 超级管理员 | 系统后台管理员角色，负责注册接种机构与生产商账号，兜底维护基础数据 |

## 2. 项目概述

### 2.1 项目背景与痛点

| 痛点 | 系统解决方案 |
|---|---|
| 用户接种选择困难：不知道哪些疫苗可接种、哪些机构有苗、哪个时段有位 | 统一提供疫苗、机构库存、班次名额查询与预约入口 |
| 机构排班与库存脱节："有位无苗"或"有苗无人" | 班次名额与疫苗库存纳入同一预约校验流程；排班页展示库存预警辅助决策 |
| 供应链信息不透明：疫苗来源、批次、流向难以追溯 | 通过"生产批次 → 供货 → 库存 → 预约 → 接种"数据链路实现全链路追溯 |

### 2.2 系统角色（共 4 个）

| 角色 | 职责概述 | 账号存储 |
|---|---|---|
| 接种用户（居民） | 浏览疫苗与机构、选择班次、提交/取消预约、查看预约状态与接种记录 | user 表 |
| 机构管理员（接种机构） | 管理护士与班次、基于供货记录入库、确认接种、库存预警处理、销毁过期疫苗 | institution_admin 表 |
| 生产商（疫苗工业生产商） | 维护疫苗产品信息、管理批次生产记录、创建供货记录 | manufacturer 表（含登录字段） |
| 超级管理员（系统后台） | 注册接种机构与生产商账号，兜底维护全部基础数据 | super_admin 表 |

### 2.3 核心业务流程

```text
生产商生产疫苗并记录生产批次（batch：批次号 + 生产日期 + 有效期）
        ↓
生产商创建供货记录（supply：批次 + 目标机构 + 数量）
        ↓
机构基于供货记录入库确认（生成 vaccine_stock，可分批入库，库存增加）
        ↓
用户选择预约（疫苗 + 机构 + 护士班次；校验库存、名额、剂次、重复预约）
        ↓
机构确认接种（写入接种时间，锁定扣减，生成接种记录）
```

## 3. 功能需求

### 3.1 接种用户（居民）

| 编号 | 功能 | 需求描述 |
|---|---|---|
| U-01 | 浏览疫苗信息 | 查看可接种疫苗种类、类型、适用疾病、剂次、储存温度要求、说明 |
| U-02 | 查询机构信息 | 按地区或名称查找接种机构，查看机构可用的疫苗品种及库存余量 |
| U-03 | 选择护士班次 | 在目标机构选择可用班次（时段），每班次有剩余名额限制 |
| U-04 | 提交预约申请 | 确认疫苗、机构、班次后提交；系统校验库存充足、班次有名额、剂次合规、无重复预约后生成预约记录（规则见 5.3） |
| U-05 | 查看预约状态 | 查看本人预约的当前状态（待接种 / 已完成 / 已取消）及取消原因 |
| U-06 | 查看接种记录 | 接种完成后查看详情：疫苗名称、批次编号、接种护士、接种时间、剂次 |
| U-07 | 取消预约 | 仅待接种预约可取消，须在班次开始前 24 小时以上（规则见 5.3），取消后释放库存与名额 |

**用户视角核心流程**：选疫苗 → 选提供该疫苗的机构 → 选该机构可用护士班次 → 系统校验通过 → 预约完成；接种完成后可查看接种记录；如无法赴约可在班次开始前 24 小时取消。

### 3.2 机构管理员（接种机构）

| 编号 | 功能 | 需求描述 |
|---|---|---|
| A-01 | 管理护士信息 | 录入、修改、删除本机构护士（姓名、工号、职称等） |
| A-02 | 管理护士班次 | 创建排班：日期、时段、最大可预约人数；班次为通用班次（不绑定疫苗品种）；排班页同步展示本机构各疫苗库存与临期/低库存预警，辅助排班规避"有位无苗"；用户预约占用名额、取消释放名额 |
| A-03 | 管理疫苗库存 | 查看各疫苗库存数量、批次、有效期；库存不足或临期时预警提示 |
| A-04 | 处理疫苗入库 | 查看生产商发来的供货记录，确认入库（可分批）：生成或累加疫苗库存记录（疫苗、生产商、批次号、数量、有效期从批次与供货记录带入），库存相应增加 |
| A-05 | 处理预约请求 | 查看本机构预约列表，接种完成后确认：写入接种时间、扣减锁定库存、预约置为"已完成" |
| A-06 | 销毁过期疫苗 | 对已过期锁定的批次执行销毁：校验无锁定库存后状态置为已销毁、数量归零、记录保留 |
| A-07 | 班次停诊 | 将班次置为"已停诊"，系统自动取消该班次全部待接种预约并释放库存与名额 |

**机构环节数据关联**：创建班次必须关联本机构护士，班次机构自动取护士所属机构；入库必须基于生产商供货记录；用户预约必须关联本机构班次，且班次对应疫苗库存充足。

### 3.3 生产商（疫苗工业生产商）

| 编号 | 功能 | 需求描述 |
|---|---|---|
| M-01 | 维护疫苗产品信息 | 录入疫苗名称、类型（灭活/减毒/mRNA）、适用疾病、剂次、储存温度要求；一种疫苗可关联多个生产商（M:N，通过 vaccine_manufacturer） |
| M-02 | 管理批次生产记录 | 记录每批次的生产日期、批次编号、有效期、生产数量（batch 表），作为供货和追溯的源头数据 |
| M-03 | 创建供货记录 | 选择本厂批次与目标机构、配送数量、配送日期，生成供货记录（supply），机构凭此入库确认 |

**生产商环节数据关联**：批次必须关联本厂已维护的疫苗品种；供货记录必须引用本厂批次；机构入库后形成"生产商 → 批次 → 供货记录 → 机构库存"完整链路。

### 3.4 超级管理员（系统后台）

| 编号 | 功能 | 需求描述 |
|---|---|---|
| SA-01 | 注册接种机构 | 创建接种机构及该机构的机构管理员账号（institution + institution_admin 同时生成） |
| SA-02 | 注册生产商 | 创建生产商及登录账号（manufacturer 含登录字段） |
| SA-03 | 兜底维护基础数据 | 对机构、生产商、疫苗等基础数据的增改查（纠错与演示数据维护） |

### 3.5 系统级功能

| 编号 | 功能 | 需求描述 |
|---|---|---|
| S-01 | 每日定时扫描 | 应用层定时任务（Spring @Scheduled，每日 02:00）扫描库存：临期批次置预警、过期批次封锁并释放锁定、取消关联预约 |
| S-02 | 库存预警 | 临期黄色预警；过期红色封锁；低库存（≤ 10 支）提示补货；阈值写入配置文件 |
| S-03 | 可预约筛选 | 无正常批次库存的机构+疫苗组合在前端隐藏，避免用户选择后无法预约 |

## 4. 数据需求

### 4.1 数据表总览（共 13 张）

| 表名 | 用途 | 关键字段 | 相对选题的变化 |
|---|---|---|---|
| user 用户表 | 居民账号与信息 | user_id, username, password, real_name, id_card, phone, gender, birth_date | 不变 |
| manufacturer 生产商表 | 生产商信息与登录账号 | manufacturer_id, name, license_no, contact_phone, address, username, password | 增加 username、password |
| vaccine 疫苗表 | 疫苗品种信息 | vaccine_id, name, type, disease, doses_required, storage_temp_min/max, description | 删除 manufacturer_id |
| vaccine_manufacturer 疫苗-生产商关联表 | 疫苗与生产商 M:N 关联 | vaccine_id, manufacturer_id（联合主键） | 新增 |
| institution 接种机构表 | 机构信息 | institution_id, name, address, contact_phone, region | 不变 |
| nurse 护士表 | 护士信息 | nurse_id, name, employee_no, title, institution_id, phone | 不变 |
| shift 班次表 | 护士排班 | shift_id, nurse_id, institution_id, shift_date, start_time, end_time, max_appointments, current_count, status | 不变 |
| batch 生产批次表 | 批次生产记录 | batch_id, manufacturer_id, vaccine_id, batch_no, production_date, expiry_date, production_quantity | 新增（M-02 落地） |
| supply 供货记录表 | 供货配送记录 | supply_id, batch_id, institution_id, quantity, received_quantity, supply_date, status | 新增（1 待入库 / 2 已入库） |
| vaccine_stock 库存表 | 机构疫苗库存（按批次） | stock_id, institution_id, supply_id, batch_id, vaccine_id, manufacturer_id, batch_no, quantity, locked_quantity, production_date, expiry_date, status | 增加 supply_id、batch_id；manufacturer_id 改为复合外键 |
| appointment 预约表 | 预约记录（核心业务表） | appointment_id, user_id, vaccine_id, institution_id, shift_id, stock_id, appointment_date, dose_number, vaccination_time, cancel_reason, status | 增加 dose_number、vaccination_time、cancel_reason；唯一索引 (user_id, shift_id) |
| institution_admin 机构管理员表 | 机构管理员账号 | admin_id, username, password, real_name, institution_id, phone | 新增 |
| super_admin 超级管理员表 | 超级管理员账号 | super_admin_id, username, password, real_name | 新增 |

> 关键外键说明：batch 的 (vaccine_id, manufacturer_id) 复合外键 → vaccine_manufacturer，保证"批次的生产商确为生产该疫苗的生产商"；vaccine_stock 的 (vaccine_id, manufacturer_id) 复合外键 → vaccine_manufacturer，从数据库层面消除 P7 冗余不一致；vaccine_stock.supply_id → supply、batch_id → batch，实现"批次 → 供货 → 库存"逐级追溯；appointment 唯一索引 (user_id, shift_id) 防止同一用户在同一班次重复预约。

### 4.2 数据关联关系

```text
manufacturer 1:N vaccine_manufacturer N:1 vaccine   （疫苗↔生产商 M:N 分解）
vaccine_manufacturer 1:N batch                      （批次归属于确定的疫苗+生产商组合）
manufacturer 1:N batch                              （批次归属于生产商）
batch 1:N supply                                    （一批可多次供货）
institution 1:N supply                              （机构接收多家供货）
supply 1:N vaccine_stock                            （入库记录可追溯至供货记录）
institution 1:N nurse        nurse 1:N shift        （机构→护士→班次）
institution 1:N vaccine_stock                       （机构库存）
shift 1:N appointment                               （班次被多名用户预约，受名额限制）
vaccine_stock 1:N appointment                       （预约锁定批次，接种后扣减）
user 1:N appointment                                （用户可有多条预约）
institution 1:N institution_admin                   （机构管理员账号）
super_admin 独立                                    （无业务外键）
```

**全链路追溯路径**：生产商(manufacturer) → 批次(batch) → 供货(supply) → 机构库存(vaccine_stock) → 预约(appointment) → 完成接种。

**关系类型说明**：显式 M:N 仅"疫苗↔生产商"一组，经 vaccine_manufacturer 分解；其余均为 1:N / N:1；无 1:1 关系。业务上的多对多（机构↔疫苗、用户↔疫苗/机构/班次）通过 vaccine_stock、appointment 两个关联实体分解，符合关系型数据库规范化设计。

### 4.3 核心业务数据要求

| 需求编号 | 数据要求 |
|---|---|
| D-01 | 预约校验库存：目标机构该疫苗存在 status = 1 且 quantity > 0 的批次 |
| D-02 | 班次可选条件：current_count < max_appointments 且 status = 1 |
| D-03 | 库存可用量与锁定量分离：quantity + locked_quantity = 该批次物理库存总量，恒成立 |
| D-04 | 批次库存状态机：1 正常 / 2 临期预警 / 3 已过期锁定 / 4 已销毁，已销毁记录不物理删除 |
| D-05 | 预约日期与班次日期一致：appointment_date 由系统取 shift.shift_date 自动写入 |
| D-06 | 剂次约束：dose_number 从 1 开始，续种须存在该疫苗前一剂"已完成"记录 |
| D-07 | 供货入库约束：某批次累计入库量（received_quantity）不得超过供货数量（quantity） |

## 5. 业务规则需求

### 5.1 FEFO 近效期优先出库

用户预约时，系统自动从该机构该疫苗所有 status = 1 且 quantity > 0 的批次中，选择 expiry_date 最早的批次进行锁定出库（事务内使用行级锁，防止并发超卖）。

### 5.2 过期疫苗自动封锁（每日定时任务执行）

| 触发条件 | 系统行为 |
|---|---|
| 距有效期 ≤ 30 天且 status = 1 | status → 2（临期预警），仍允许出库 |
| 超过有效期且 status ∈ {1, 2} | status → 3（已过期锁定），禁止出库；若存在 locked_quantity > 0：释放锁定（locked_quantity 回加至 quantity），关联待接种预约自动取消（status = 3，cancel_reason = "疫苗批次过期"），班次名额同步释放 |
| 管理员对 status = 3 批次执行销毁 | 校验 locked_quantity = 0（否则先取消关联预约释放锁定）；quantity 置 0，status → 4，记录保留 |

### 5.3 预约锁定-确认扣减（两阶段库存操作）

**预约前置校验（按顺序全部通过才允许预约）**：

1. 库存校验：FEFO 选中批次存在且 status = 1、quantity > 0；
2. 班次校验：shift.status = 1 且 current_count < max_appointments；
3. 剂次校验：首剂——该用户该疫苗无任何"待接种/已完成"记录；第 N 剂（N ≥ 2）——存在该疫苗 dose_number = N−1 且 status = 2 的记录，且 N ≤ doses_required；
4. 重复预约校验：该用户该疫苗不存在 status = 1 的预约；同一班次唯一索引 (user_id, shift_id) 兜底；
5. 时段冲突校验：该用户在该班次日期+时段无其他待接种预约；
6. 日期一致：appointment_date 自动取 shift.shift_date。

**阶段操作表**：

| 阶段 | 触发 | 数据变更 |
|---|---|---|
| 预约锁定 | 用户提交预约 | 库存 quantity − 1、locked_quantity + 1；班次 current_count + 1；新增 appointment（status = 1，dose_number、stock_id、appointment_date 写入） |
| 确认扣减 | 管理员确认接种完成 | 库存 locked_quantity − 1；appointment status = 2，vaccination_time = 当前时间 |
| 用户取消 | 用户取消预约（status = 1 且班次开始前 ≥ 24 小时） | 库存 quantity + 1、locked_quantity − 1；班次 current_count − 1；appointment status = 3，cancel_reason = "用户取消" |
| 停诊取消 | 管理员停诊（shift.status → 3） | 该班次全部待接种预约：释放库存锁定（quantity + 1、locked − 1）、班次名额清空相应数量、appointment status = 3，cancel_reason = "班次停诊" |
| 过期取消 | 定时任务封锁过期批次 | 同 5.2：释放锁定、取消预约（cancel_reason = "疫苗批次过期"）、名额释放 |

**关键约束**：quantity 始终表示实际可用量；locked_quantity 表示被预约占用量；所有阶段操作必须在一个事务内原子完成，并配合行级锁防止并发超卖。

### 5.4 预警机制

| 预警 | 触发条件 | 行为 |
|---|---|---|
| 临期黄色预警 | 距有效期 ≤ 30 天 | status → 2，管理端标黄 |
| 过期红色封锁 | 超过有效期 | status → 3，禁止出库 |
| 低库存预警 | 某机构某疫苗全部正常批次 quantity 合计 ≤ 10 | 管理端提示补货 |
| 无库存隐藏 | 某机构某疫苗无正常批次库存 | 用户端隐藏该机构该疫苗选项 |

> 阈值常量（临期 30 天、低库存 10 支、取消截止 24 小时）写入配置文件 application.yml，调整时改配置即可，无需改代码。

## 6. 非功能需求

### 7.2 选题文档中发现的明显问题（P1–P16）

| 编号 | 问题 | 解决方案（已定案） |

| P5 | 剂次管理缺失 | 【代决】同 D5：appointment 增加 dose_number 字段；续种须存在已完成的前一剂 |
| P6 | 班次名额字段冗余且规则不完整 | 【代决】保留 shift.current_count（查询性能），由应用层事务统一维护：预约 +1、取消/停诊自动取消 −1，规则已写入 5.3 |
| P7 | 库存表生产商字段冗余 | 【代决】因 P15 改为 M:N：vaccine 删除 manufacturer_id，新增 vaccine_manufacturer 中间表；vaccine_stock.manufacturer_id 保留（批次归属生产商）并加复合外键 (vaccine_id, manufacturer_id) → vaccine_manufacturer，冗余不一致从数据库层面消除 |
| P8 | 预约日期与班次日期无一致性约束 | 【代决】预约时 appointment_date 由系统取 shift.shift_date 自动写入，前端不开放输入，从源头保证一致 |
| P9 | "通知用户"无消息机制支撑 | 【代决】本期不做主动推送；appointment 增加 cancel_reason 字段，用户登录后可查看被取消预约及原因；消息推送列为后续扩展 |
| P10 | 停诊班次的预约处理未定义 | 【代决】管理员停诊时，系统在事务内自动取消该班次全部待接种预约（cancel_reason = "班次停诊"），同步释放库存锁定与班次名额，规则已写入 5.3 |
| P11 | 重复预约与时段冲突无约束 | 【代决】数据库唯一索引 (user_id, shift_id)；应用层校验同一用户同一时段无其他班次待接种预约 |
| P12 | 枚举与安全细节缺失 | 【代决】状态/性别字段保留 TINYINT，配套 Java 枚举字典统一维护；密码采用 BCrypt（Spring Security BCryptPasswordEncoder） |
| P13 | 销毁时锁定量未处理 | 【代决】销毁前校验 locked_quantity = 0，否则先自动取消关联预约并释放锁定，再执行销毁，规则已写入 5.2 |
| P14 | 班次的机构外键冗余 | 【代决】保留 shift.institution_id（避免多表 JOIN）；创建班次时由系统取护士所属机构自动写入，保证一致 |
| P15 | 疫苗与生产商关系被简化 | 需支持多厂商：新增 vaccine_manufacturer 中间表（M:N），vaccine 删除 manufacturer_id |
| P16 | 批次生产记录无独立表 | 【代决·新增发现】M-02 要求管理批次生产记录，但原 8 表无批次表，供货时批次信息凭手工填写、无法校验。新增 batch 生产批次表；supply 引用 batch_id；入库时从 batch 复制批次信息 |
