# 疫苗管理系统（Vaccine Management System）

面向「疫苗从生产到接种全链路管理」的 Web 系统，以 **用户选疫苗 → 选机构 → 选护士班次 → 预约接种** 为核心流程，串联 **生产商供货 → 机构入库 → 用户预约 → 护士接种** 四个环节，实现每支疫苗来源可查、去向可追。

## 功能特性

- **4 类角色**：居民 / 机构管理员 / 生产商 / 超级管理员，登录后按角色隔离接口与数据；
- **供应链管理**：生产商维护疫苗（多厂商 M:N）与批次生产记录 → 创建供货记录 → 机构凭供货记录分批入库；
- **智能预约**：FEFO 近效期优先出库、事务 + 行级锁防并发超卖、剂次推算、重复预约与时段冲突校验、班次开始前 24 小时截止取消；
- **接种闭环**：机构确认接种 → 锁定扣减 → 生成接种记录（疫苗、批次、护士、时间、剂次）；
- **全链路追溯**：生产商 → 批次 → 供货 → 库存 → 预约 → 接种，逐级可查；
- **库存预警**：临期黄色预警、过期红色封锁、低库存提示；每日 02:00 定时扫描 + 管理端手工扫描；过期批次自动释放锁定并取消关联预约；
- **异常处理**：班次停诊自动取消预约、过期疫苗销毁（锁定校验）。

## 技术栈

| 层次 | 技术选型 |
|---|---|
| 数据库 | MySQL 8.x（utf8mb4），13 张表，外键 / 唯一索引 / CHECK 约束落地 |
| 后端 | Java 25（Temurin）+ Spring Boot 3.x + MyBatis-Plus，JWT（jjwt）登录态，BCrypt 密码加密 |
| 定时任务 | Spring `@Scheduled`（每日 02:00 库存扫描） |
| 前端 | Vue 3 + Vite + Element Plus + axios + Pinia，按角色分 4 端页面 |
| 构建工具 | Maven（后端）、npm（前端） |

## 快速部署（从零开始）

### 1. 创建数据库

```sql
CREATE DATABASE vaccine_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 2. 执行初始化脚本（建表 + 演示数据）

```bash
mysql -uroot -p vaccine_db < sql/01_schema.sql
mysql -uroot -p vaccine_db < sql/02_data.sql
```

> 两个脚本均幂等，可重复执行。`01_schema.sql` 建 13 张表；`02_data.sql` 灌入演示数据（账号见下表）。

### 3. 修改配置

- `server.config.json`：后端端口 `backend.port`（默认 8080）、JDK 路径 `backend.javaHome`、前端端口 `frontend.port`（默认 5173）、Node 路径 `frontend.nodeHome`、数据库 `database.*`；
- `backend/src/main/resources/application.yml`：数据源账号密码（`spring.datasource`）、JWT 密钥与过期时间（`jwt.*`）、预警常量（`vaccine.*`：临期 30 天 / 低库存 10 支 / 取消截止 24 小时）。

### 4. 启动后端

```powershell
.\server.ps1 start backend
```

或手工启动：

```bash
cd backend && mvn spring-boot:run
```

启动成功后 `GET http://localhost:8080/api/ping` 返回 200。

### 5. 启动前端

```powershell
.\server.ps1 start frontend
```

或手工启动：

```bash
cd frontend && npm install && npm run dev
```

### 6. 访问系统

浏览器打开 **http://localhost:5173** ，使用下表账号登录。

> 服务状态随时可用 `.\server.ps1 status` 查看；重启用 `.\server.ps1 restart all`。

## 演示路线（5 分钟走通主流程）

### 方式一：一键脚本（推荐）

```powershell
.\demo.ps1 -Reset   # 可选：重置数据库为演示初始状态后开始
.\demo.ps1          # 自动走通全链路，约 2-3 分钟，逐步输出
```

脚本自动完成：超管注册机构 / 生产商 → 生产商建疫苗、批次、供货 → 机构入库、排班 → 居民注册、预约（FEFO 锁定最早效期批次）→ 规则拒绝演示（重复预约 / 时段冲突）→ 机构确认接种 → 全链路追溯 → 居民查看接种记录 → 第 2 剂预约 → 预警扫描（临期 / 低库存）→ 过期批次自动封锁并取消预约 → 居民查看取消原因 → 销毁过期疫苗 → 数据一致性核对。全程无人工改库。

### 方式二：界面手动演示

1. **超管**（`superadmin`）登录 → 注册一家接种机构（自动生成机构管理员账号）与一家生产商；
2. **新生产商**登录 → 维护疫苗（勾选本厂）→ 建生产批次（批次号、生产日期、有效期、数量）→ 创建供货记录（选批次、目标机构、数量）；
3. **新机构管理员**登录 → 「供货管理」确认入库（可分批）→ 维护护士 → 创建班次（排班页同步展示库存预警）；
4. **居民**登录 → 查询疫苗与机构 → 选班次预约（系统按 FEFO 自动锁定最早效期批次，展示剂次）；
5. **机构管理员** → 「预约管理」扫描核销 / 确认接种；
6. **居民** → 「我的预约 / 接种记录」查看状态、批次、护士、剂次与取消原因；
7. **机构管理员** → 「库存预警」执行扫描，演示临期（黄）、过期（红，自动取消预约）、低库存提示；对过期批次执行销毁；
8. **机构管理员** → 库存追溯，演示 生产商 → 批次 → 供货 → 库存 → 预约 → 接种 全链路。

## 业务规则速览（与《.dev_docs/需求文档.md》5.x 一致）

| 规则 | 说明 |
|---|---|
| FEFO 出库 | 预约时自动锁定 `status IN (1,2) 且 quantity > 0 且未过期` 批次中有效期最早的一个（事务 + 行锁） |
| 预约前置校验 | 库存充足 → 班次有名额（status=1 且未满）→ 剂次合规 → 无同疫苗待接种预约 → 无同时段预约 |
| 剂次 | 首剂无记录；续种须存在前一剂「已完成」记录；超过 `doses_required` 拒绝 |
| 取消预约 | 仅「待接种」可取消，须在班次开始前 ≥ 24 小时；取消后释放库存与名额 |
| 批次状态机 | 1 正常 → 2 临期（距有效期 ≤ 30 天，仍可出库）→ 3 过期锁定（禁止出库，自动释放锁定并取消预约）→ 4 已销毁（记录保留） |
| 停诊 | 班次置停诊后自动取消该班次全部待接种预约并释放资源 |
| 预警阈值 | 临期 30 天 / 低库存 10 支 / 取消截止 24 小时，均在 `application.yml` 的 `vaccine.*` 配置 |
| 数据守恒 | 每批次 `quantity + locked_quantity` = 物理库存（预约锁定 +1、确认扣减 −1、取消释放 +1） |
